# Zone Snapper

都市天际线2（Cities: Skylines II）模组。让游戏**自带的**区域绘制工具在你放置节点时自动吸附到道路、铁路、人行道外缘、真建筑的轮廓与已有区域边界，把区域边线**沿网络描边**而不是用直线连接点击的节点，并且在**你点下去之前**就用淡色画出「点下去会贴成什么样」。

参照对象是 Paradox Mods 上已下架的 **Subdivisions**（ModId 148238，作者 Sidrus，GitHub 仓库也已删除）。本模组按它的商店页说明与完整更新日志重建其机制，并按需求做了改进（见下）。

> ⚠ 这一版的行为**仍在逐轮实机验收中**：私有列表不等于"验完了"，八轮反馈的账都记在 `开发笔记.md`。
>
> **v0.3.0 是按你第八轮反馈（十条 + 两张截图）重写的版本。** 这一轮先挖到一个根因，再按那个根因改一个模型，
> 而不是十条各打一颗补丁：上一版「你自己点的格不再被模组挪走」落地之后，描边的两个端点基本都成了自由点，
> 而旧写法要求**两端都贴在能描的东西上**才肯描边 ⇒ 正常描边这条路几乎永远走不到，
> 唯一还能产出网络点的只剩「节点续接」。于是同一个缺陷长成四个症状：
> **关掉节点续接 → 预览和自动贴合直接不生效**（续接就是唯一的网络来源）；
> **开着节点续接 → 变成强制续接**，明明有贯通的路也强行在交叉口断掉再直连（能连通的两端被丢进续接那条贪心支路，它从来不走 A*）；
> **两个节点离得远就干脆直线连**（哪怕有条贯通的路）；**产业区/表面区域几乎看不到贴合路径**。
>
> 改法是一个模型：**你那格一动不动，走线自己在你旁边长出一个按规则吸附的接入点**，
> 然后 `玩家端点 → 接入点 → 沿网络（经路口中心点）→ 接入点 → 玩家端点`。
> 续接退回成"附近真没东西可贴"时的兜底。这一轮同时做了的：
> **路口只有一个代表点**（你截图里那一圈偏心的节点：游戏把主节点 + 人行道/辅路/重叠层拆成 2~5 个节点，
> 旧写法拐在哪一个取决于遍历顺序；现在归并成一个中心点，任何方向连过来都经过它，而它要不要真占一格仍按「直线不放节点」判；
> 实机凭据是统计行的 `junc=`，数的是"拐在路口的那一格被挪到中心"的次数）；
> **距离不再是门槛**（绕行预算退回纯比例，比例本身与尺度无关；你举的四分之一大弯路 45° 相切那种形状实测绕行比 1.414，放行）；
> **地下物体一律出局**（隧道、下沉/开槽段、建在地下的建筑，三类工具既不能吸也不能描）；
> **产业区/表面区域既能贴到、也绝不沿马路中间走**（中心线上的锚点会被重挂到人行道外缘或建筑轮廓，
> 交付前整条折线逐段自查有没有横跨马路/建筑）；
> **你那笔连线压到别的区域不再一票否决**（只判贴出来的路径干不干净，干净就能建）；
> **拖拽与预览一致**（拖到的那一格留在原地，左右两边各接进网络同一个坐标时只留一个 —— 那种"零宽度裂缝"能存档却三角化不出东西）；
> **模组不再写游戏自己的吸附距离**（第六轮那条要求按你这一轮的话撤掉，顺带根除了"粗虚线越来越粗"）；
> 快捷键页「重置」按钮下面新增**「关于」板块**（模组版本 / 作者 / 三个跳转按钮）。
>
> GPT 那份算法正文我没能读到（分享链接两种取法都被沙箱拦了），**没有照着它改**；
> 这一轮的算法是按游戏数据 + 上面那个根因重写的。你把正文贴进来我再对着比一轮。
>
> 本版**只有三个工具开关**：**市辖区、专门产业区、表面区域**（默认都开）+ 可选的**城市边界线**。
> 游戏里的垃圾场填埋区归「专门产业区」那一档、地皮表面区归「表面区域」那一档 —— 它们在同一个工具里只是不同的 `AreaType`，不需要各给一个开关。
> 公园、散步区、公交线路那类不需要贴合的工具，本版刻意不做。

## 解决什么问题

原版画区域（行政区、地块、地表贴图区……）是「点若干节点 → 连成闭合多边形」，边界永远是直线段，要贴着路网就得手动点几十上百个节点。

## 工作原理（一句话版）

模组持有「你真正点过的手动节点栈」，每帧把它投影成游戏工具的那张控制点表：`[手动点, 沿网络描出的自动点…, 手动点, …, 游标]`。游戏按这张表预览、按这张表落档，所以不需要任何额外按钮或独立工具。

## 四个词的含义（第五轮反馈 4 定的口径）

后面所有行为描述都用这四个词，不再混用「节点/点/角」。

| 词 | 是什么 | 会不会写进区域 |
|---|---|---|
| **手动节点** | 你左键真的点下去的那些格。**区域创建完成后，所有自动节点也都算手动节点**（可以单独拖动、也是后续重描的锚） | 会 |
| **自动贴合路径** | 两个手动节点之间那一串自动点 | 会 |
| **手动路径** | 两个手动节点之间**没有任何**自动点 ⇒ 就是一条直线 | 会（两个端点而已） |
| **交点** | 自动贴合路径上**折线处**那一格：直线与曲线交汇处、曲率变化处、拐过弯的接头都算 | **交点必放节点；没有交点就不放** |
| **切换处** | 从一条道路/轨道跳到另一条（含换成不同高度的那一条）的位置 | 必放节点。它与交点可以同坐标，游戏会自动合并同坐标节点 |

## 三个开关覆盖的六种区域类型，各自的贴合口径

| 你要的区域（属于哪个开关） | 节点吸到哪 | 节点吸附距离默认 | 两个相邻点之间没有连续路径时 |
|---|---|---|---|
| **市辖区**（市辖区开关） | **道路/轨道中心线**（与游戏自身的行政区吸附一致），含高架；可在相同或不同高度之间切换；**地下的东西一律不算**（隧道/下沉段） | 100% = 游戏给市辖区设的距离 | 先由走线自己长出**接入点**贴上去（第八轮之后这才是主路）；真的一端附近什么都没有才轮到最后那一段**节点续接** |
| **专门产业区**（专门产业区开关） | **人行道外缘**（不是车道路缘）或 **同一栋建筑的外轮廓**，含高架；只考虑地表 | 100% = 游戏给产业区设的距离 | 同上；另外贴出来的路径**不许横跨**道路或建筑（横穿了就不给贴，退回你的直线） |
| **垃圾场填埋区**（同样走专门产业区那一档） | 同专门产业区（游戏里同为 `AreaType.Lot`） | 跟专门产业区共用那一档 | 同上 |
| **表面区域**（表面区域开关，含地皮表面区） | 同专门产业区的边缘目标（游戏里是 `AreaType.Surface`） | 100% = 游戏给表面区域设的距离 | 同上；**允许跨越**，跨越那一段保持直线 |
| 城市边界线（可选，默认关） | 游戏本身完全不让它吸附；开了本模组才吸并描边（**这一档是唯一仍会吸你手动那格的**，你的原话「除了城市边界」） | 单独一档滑杆 | 同上 |

**同一档区域内节点必须完全吻合**：两块市辖区沿同一段道路中心线贴合时，那段上的节点位置逐格相同（判据是纯几何的、与区域身份无关，见回归壳 X/T 段）；两个手动点都落在另一个专门产业区的边界上时，吸的是**那个产业区那一段**的节点；表面区域因为允许与道路/建筑交叉，同样按完全吻合处理。

弯道上的节点密度由**「曲线精细度」**这一档决定（默认 0 = 只在交点放点，拉高才在平滑弯道上补点），它同时决定「多小的转角算交点」。旧的「相邻两点连线不许越出道路边缘」这条硬界仍然保留，只是按精细度插值。道路变铁路的那一格**必有节点**；地面路变高架的那一格也**必有节点**；高架照样贴合。**隧道与下沉段整个不是目标**（第八轮反馈 3；上一版只禁到路缘档，那一档例外已经撤掉）。

## 与参照模组 Subdivisions 的差异

| 需求 | 本模组做法 |
|---|---|
| 不要额外按钮 | 跟随游戏当前激活的区域工具自动生效，没有入口按钮 |
| 覆盖所有节点式绘制 | 游戏里节点式区域工具只有 `AreaToolSystem` 一个，它按类型覆盖 市辖区 / 产业区(含填埋区) / 表面区域(含地皮) / 城市边界线，逐类可单独开关；太空区按第五轮反馈整条删除 |
| 右键删手动节点 | 描边点永远是手动栈的派生物；右键弹一个手动节点，那条边的描边点整批一起消失 |
| 贴合优先级 | **不再做成三个开关**（第五轮反馈 5）：换成「贴合模式」下拉框五档 —— 智能（默认）/ 路径最短 / 节点最少 / 交点最少 / 不切换网络。每档就是一组具体数字（绕行上限、转弯代价、换类代价、许不许为包住街区外侧多搜一遍、拐点判定角度），可断言可复述 |
| 已有区域边界要不要吸 | **永远允许**（反馈 4 明确要「两个手动点都贴在另一个专门产业区边缘上时贴合它的节点」），这是功能不是偏好，所以那一档开关被删了 |
| 中间有小巷不许穿 | 一条边在走廊里按左右两侧各搜一遍，取**离本区域中心最远**的那条 ⇒ 走最外围路段，不穿小巷，也不绕大圈。「贴合模式=路径最短/不切换网络」时不搜外围 |
| 环形道路/环岛 | 沿**环岛自己的中心线**走（第五轮反馈 7：不再刻意绕到外围那一圈路）；两点落在同一个环上、直切会把区域压成一条缝时，绕的也是这个环的另一侧 |
| 同一段路两侧要吻合 | 同侧、中心线档下由确定性保证完全重合；**跨路段两侧**这种情形还在实机核验（见已知限制 5） |
| 路网变了自动跟随 | **v0.2.1 起不再自动**：改路/改建筑之后已提交区域**一个字都不改**，只在日志里提示一句；写盘的唯一入口是「重算贴合区域」快捷键（由开关「允许「重算贴合区域」键改写已保存的区域」管，**默认开**——关着那颗键什么都不会做）。按键重算成功后会把那块区域的边界描一圈、被挪动的节点闪几下，并且**可以用快捷键退回上一次调整**（退回的只是最近一批）。跟随系统跑在 `ToolUpdate` 相位（第五轮修的根因：原来挂的 `ApplyTool` 只在「有提交的帧」存在） |
| 拖拽已存在的角点 | **拖动过程中**就有淡色预览指出「松手后左右两条边会贴成什么样、这一格会落在哪」；**松手后真的落档**（v0.2.1 修的：旧版自检拿整环判自交、几乎必拒，预览有落档没有）。落档只重描被拖那一格的**左右两条边**，其余每一格保持存档里原样——包括落在吸附距离内的角点，**不再**被重新吸附 |
| 点下去之前先看结果 | 移动中的预览 = 最后一格 → 游标那条边的完整描边结果 + 会被自动插入的节点；与落档走**同一段代码**，所以「淡线说贴、点下去不报」这种分裂在离线断言里就挡掉。**退出工具或按 ESC 后预览一定会消失**：生产端每条「这一帧什么都不做」的路径都统一清信箱，渲染端另外还有一道「工具不在/几何过期」的新鲜度闸 |
| 吸附距离分级 | 基准值用游戏为每种区域自己配的 `AreaGeometryData.m_SnapDistance`，**每类一条滑杆乘在它上面**（50%~300%），再按 8~260 米夹取，不硬编码米数、不再叠加第二层倍率。**v0.3.0 起这一个数只管模组自己的吸附**：第八轮反馈 3/10 明确「手动节点归游戏自己的对齐管」⇒ 上一版「把倍率写进游戏 prefab（连游戏内置对齐一起放大）、离开工具再还原」那套借与还**整套删除**，游戏的数据一个字节都不动（门禁里留了一条反向哨兵，那段代码要是被粘回来就红）。副作用顺带根除：区域边框那种粗虚线不会再一直粗着 |
| 手动点的那一格 | **不动它**（第八轮反馈 3/10 重申两次）。除「城市边界线」那一档，模组从不把你放的节点吸到中心点或任何别的地方——你想要那个对齐可以打开游戏自己的工具 |
| 那么"贴合"从哪来 | **接入点模型**：你那格留在原地，走线在它附近按这一档的规则**自己长出一个吸附节点**接进网络，然后 `你的端点 → 接入点 → 沿网络（经路口中心）→ 接入点 → 你的端点`。所以「关掉节点续接以后什么都不贴」「两个节点离得远就直连」「产业区几乎看不到贴合路径」这三件事是同一个根因，一起没了 |
| 一个路口只有一个点 | 游戏里一个十字路口是 **2~5 个**节点（主网络 + 人行道/辅路 + 重叠层 + 按节点偏移拆出的分段点）。模组把它们归并成**一个中心点**（只按主接头取平均，副网络那些偏几米的成员不参与，高度取最高度数那一格），走线与吸附候选一律取这个中心 ⇒ 任何方向连过来都在同一个坐标拐弯，不再"选一个偏心的节点就拐"。**它要不要真占一格节点，之后仍按「直线不放节点」判**（第八轮反馈 5 那张截图要的是两件事，顺序不能反）。实机凭据是统计行的 `junc=`：数的是"拐在路口的哪一格被挪到了中心点"，画过带路口的边界它却不涨 ⇒ 那种路口比我们 15 米的归并口子还宽 |
| 地下物体 | **一律不是目标**（第八轮反馈 3）：隧道、下沉/开槽段（最低端高程 < -0.5 米）、建在地下的建筑，三类工具的节点吸附与自动贴合都不认。高架**不受此限**（第五轮反馈 4 要求高架能贴） |
| 连线压到别的东西还算不算能建 | **只判贴出来的路径**（第八轮反馈 9）：你自己那两个点之间的直线跨过别的区域/马路，不再是一票否决；只要自动贴合那条线干净（不自交、不横跨马路或楼、不压成薄片）就能建 |
| 两点弯曲连接 | 游戏区域数据是折线（`Game.Areas.Node` 只有坐标+高程），**做不到真曲线**。原来的「自由点之间走弧线」按第五轮反馈删除。第八轮之后贴合的**主路是接入点**（端点不动，走线自己接进网络），**「节点续接」退成兜底**：只有那一格附近真没有这一档该贴的东西时，才沿能贴的方向走一段、在中断处留一个真节点、剩下的用直线接上（仍受绕行上限与转角闸约束；贴不出至少 6 米就干脆不续接，免得边界上出现无缘无故的小折角） |
| 看得懂的设置项 | 选项页每一项都是**标题 + 一行说明**，12 种语言各有一套文案（不是本地化 key），且回归壳逐行断言「缺哪种语言都会红」。**三个工具名跟游戏自己的译名**（从随包的 `Locale.cok` 里逐格抽出来对账：市辖区在日语里是「特区」、繁体是「行政區」，产业区日语是「特化産業エリア」，意大利语 Quartieri，俄语 Районы），不是我们自己另起一套；只有你点名要的两个名字保留玩家说法（见下一节末尾） |

## 安装

构建后模组会部署到 `…\Cities Skylines II\Mods\ZoneSnapper\`（游戏内订阅/本地 WIP 两个位置都可用）。停用本地副本的唯一可靠办法是给文件夹名前加 `.`。

## 设置项（游戏内 选项 → 模组）

每一项都是**一句人话标题**（大多数还带一行说明；**三个区域类型开关只有标题**——说明文字按第六轮反馈删掉了），12 种官方语言各有一套文案。标签页从三个变成三个新的：**吸附 / 其它设置 / 快捷键**。

**吸附** 标签页：
- 总开关（**默认打开**）；
- 生效的区域工具：市辖区、专门产业区、表面区域（三个默认都开）；
- **节点吸附距离**三条各自独立：市辖区 / 专门产业区 / 表面区域，50%~300%，**100% 就是游戏原版给这一类设的距离**；
- **贴合模式**下拉框：智能（默认）/ 路径最短 / 节点最少 / 交点最少 / 不切换网络；
- **特殊吸附目标**（放在这一页最下面）：城市边界线开关 + 它自己那条吸附距离滑杆（默认关）。

**其它设置** 标签页：曲线精细度(%)（0~100，**默认 0** = 只在交点放点）；节点续接；**允许「重算贴合区域」键改写已保存的区域**（**默认开**——v0.2.1 起写盘只由那颗键发起，这一档关着的话那颗键什么都不会做，所以默认改成开）+ 高亮被跟随改过的区域；移动时实时预览 + 预览不透明度(%)。
原来这一页里的「绘制过程中实时跟随路网」删了（绘制时不可能去改路）；「显示贴合提示」重新定义成上面那条高亮+闪烁；
旧的「已提交区域自动跟随（实验性）」就是现在这一档——**自动**那半已经整个删掉，改路只提示、按键才写盘。

**快捷键** 标签页四个动作：启用/关闭本模组、循环切换贴合模式、重算贴合区域、**退回上一次自动跟随的调整（强烈建议设置）**。
**四个动作默认都不绑定按键**（v0.1.1 起，按玩家要求）——请自己在这一页设；不设也能用，只是少几个快捷动作。

四颗快捷键下面还有一颗 **「把所有设置恢复默认值」**（v0.2.1 出机前追加）：点它会先弹一次确认框，确认后
本页所有选项回到默认值，**并且那四颗快捷键一起被清空、需要重新配**（弹窗与说明里都写明了这一条）。
它同时会丢掉当前画到一半的会话缓存并立刻写盘；这一步**无法撤销**，也没有「退回重置」那颗键。

重置按钮下面是**「关于」板块**（v0.3.0，第八轮反馈 1）：模组版本、作者（yuexian），以及三颗跳转按钮
——「请我喝杯咖啡」(Ko-fi)、「论坛页面」、「RAINBOW 官网」，点了用系统浏览器打开。
论坛那一颗的说明**照实写**：本模组还没发布，所以现在的论坛链接指向的是参考对象那类的社区页而不是我们自己的帖子——
等真上架了再把它换成模组页。

**两处故意没跟官方走**：**节点吸附距离** 与 **城市边界线** 是你在反馈里点名的说法，保留玩家词；
游戏那一侧的叫法写在同一格里对账（城市边界线那一档写的是 `城市边界线（地图区块）`，
它的开关说明里写明了这一档在游戏里叫「地图区块」、且游戏本身不允许它吸附）。这样两套说法你都能在游戏界面上找到对应的东西。

还有一处要说明白：**「吸附 / 贴合」这一层动词与「人行道外缘」是我们的说法，不是抄游戏的**——
游戏随包的可读文案（`Locale.cok`）里根本没有 Snapping 这个词（12 种语言 0 命中），curb/kerb 也是 0 次，
那一层界面文字在压缩资源里读不到。我们只把**抄得到的东西**（三个工具名 + 地图区块的官方名）对到了游戏原文上，
抄不到的就老实用自己的话讲清楚，不冒充官方。

## 已知限制

1. 「两点真曲线」做不到（游戏数据结构是折线），用自适应简化的折点逼近；外沿档靠「弦不许越出路缘」把密度顶上去。
2. **淡色预览和游戏自己那条直线并存**：预览刻意不写进控制点表 —— 写进去的话，最后那一格会被游戏的最小间距校验静默吃掉（v0.1.1 的事故形状），
   而且左键会把表里的预览点全数收成真节点，而你可能根本不点。代价就是你同时还能看到游戏那条「游标直连」的虚线：**淡线才是点下去之后的结果**。
   预览在 Rendering 相位绘制，最多比工具晚一帧（宁可晚一帧，也不给每帧再加一次图搜索）。
   v0.2.1 起拖拽的预览与落档是**同一个范围**：都只动被拖角点的左右两条边，其余格保持原样 —— 「预览有、落档没有」的分裂修掉了。
3. **已提交区域的重写只由两颗键发起，绝不自动**（v0.2.1，第六轮反馈 5 的口径）：
   改路/改建筑之后区域不会自己动，只在日志里提示一句；按「重算贴合区域」键才会按当前路网重描视野内的区域。
   三道保险不变：形状本来就已经对了 ⇒ 一个字都不写；重描结果自交或退化 ⇒ 整块保持原样；改写成功后可用**快捷键退回最近一批**（只有一批的额度）。
   另外**与邻接区域的节点取齐只在「绘制」那一路生效**：跟随与拖拽重描那一路**不抓邻接边界**——
   理由是自吸回自己的旧边界会让跟随空转（每次重描都抄一遍自己上一次的点，形状永远「对了」，路改了也跟不上）。
4. 编辑**已存在**的区域（填埋场、特殊产业用地那类「从建筑上改用地」）走的是**接管**：
   开局原样收下游戏已有的控制点、不重新吸附，贴合只作用在你之后新点的点上。
5. 「同一段路两侧的区域节点完全吻合」在同侧/中心线档下成立；两块区域分别压在公共段**两侧**时，
   「最外围」是各自相对自己区域中心算的，理论上可能选到不同路线 —— 实机若出现请报具体是哪条路。
6. **能对照的官方词只有工具名**：三个工具名与"地图区块"那一格在 12 种语言里逐格对过游戏随包的文案表
   （回归壳 L6 段 31 条钉着，改一个词就会红；另外两条守卫专门拦"把没取证的词写成官方词"）。
   但**「吸附 / 贴合」这一层动词与「人行道外缘」游戏里没有可读的对应词条**（`Locale.cok` 全库 0 命中，那层 UI 文字在压缩资源里），
   所以那是我们自己的说法；而且除中英文外的 10 种语言**整句说明**仍未经母语者校对——
   也就是说"这一档游戏里叫什么"是可靠的，"这句话读起来顺不顺"不是。
7. 外沿档每格要多探两条缘线、还要收集建筑轮廓，单帧耗时比中心线档高；预览每帧再跑一次描边，上一帧超过 4 毫秒就这一帧沿用旧几何，
   所以大区域和拖动时看到的是「慢半拍的预览」而不是掉帧。大区域描边与预览的实际耗时仍待实机数字。
8. **从 v0.1.x 升上来会重置你调过的数值**：设置是按属性名存盘的，而第五轮把「贴合范围倍率 / 行政区额外倍率 / 简化程度 / 单边节点上限」
   这些项删掉或改名了（换成三条各自的节点吸附距离、曲线精细度）。旧文件里那些键会被忽略，新项一律回到默认值。
   这是刻意选择的后果：与其偷偷把旧数字搬到语义已经反过来的滑杆上（简化程度 ↔ 曲线精细度方向相反），不如明说「重调一次」。
   （0.2.0 → 0.2.1 没有改名或删项，你调过的数值**照搬**；唯一的默认值变化是第 3 条那个开关，因为它的语义反过来了。）
9. **闭合那条边的补写至今没有实机证据**：离线壳覆盖了它的算式，但实机日志里「闭合边已补写」这一行在六轮测试里从没出现过
   （只出现过「闭合预览」）。v0.2.1 拆掉了「帧序自杀」这个根因——待补写环过去在提交那一帧就被会话清理丢掉，写那一步根本走不到——
   但「模组到底能不能写游戏的区域节点表」仍要第七轮实机定案，它还是清单第一优先项。
10. `Engine/CurveKit.cs`（弧化与平滑）与 `Engine/WorldModel.cs` 里的 `IsoKit`（等值线）在产品代码里**已经没有调用者**了：
    前者随第五轮反馈 7「自由点之间走弧线」删除，后者随 v0.1.4 海岸线删除。它们仍被回归壳测着（纯几何，不占运行时开销），
    下一轮若确认不需要，就连同对应的 C/C2/I/I2 段与门禁类型清单一起删掉。
11. **吸附目标白名单是我们自己的口径，且「厂区内部路」的判据是 fail-open 的**：
    游戏自己的区域吸附并不按网络类型过滤（什么 net 都吸），白名单（步道/水道/埠头/内部路/摆件不是目标）完全是本模组加严的。
    「内部路」的判据是 net 的 SubOwner 位、或 Owner 链能走到一栋建筑；**两条都判不出来时按「不是内部路」处理**——
    宁可漏排一条内部路，不误杀一条真路。所以在某些厂区里，内部路可能仍然是吸附目标。
12. **吸附距离滑杆只管模组自己**（v0.3.0 起）：它只放大/缩小我们算吸附半径用的那个基准，
    **游戏内置的节点对齐不再跟着变**——第八轮反馈 3/10 明确「手动节点不需要模组强制吸附，玩家自己会开对齐工具」，
    第六轮那条「滑杆也要管游戏内置对齐」的要求按他的话撤掉，整套写/还 `AreaGeometryData.m_SnapDistance` 的机制已删除
    （门禁里留了反向哨兵：那段日志字面量一回来就红）。副作用是这条滑杆现在**不再影响你手动点的落点**，
    它影响的是"走线长出接入点的那个半径"和自动点的密度。
13. **「把所有设置恢复默认值」那颗按钮有两处只有实机能定的地方**：
    ①点完之后**面板上的控件**是否当场回到默认值（游戏的控件是通过取值委托读属性的，理论上会刷新，但「不是玩家自己改的那一次」没实测过；
    重开一次面板必然是默认值）；②清空快捷键要清三处（存档里那份绑定、输入映射表里那份、那颗动作的开关），
    前两处都走游戏自己的入口，日志 `设置已重置 … cleared=4/4 mapOk=N` 里 `mapOk<4` 就说明映射表那处这次会话没清掉——
    **重启一定好，且我们已经把那颗动作摁成不触发，所以不会误按**（第三处正是防「按任意键都触发」那道事故的）。
    顺带一条与这颗按钮无关的老限制：**同一会话里刚配的快捷键要重启才生效**（动作句柄只在加载时挂一次）。
14. **第八轮的三处判断是我定的，不是你说的话里就有的**（错了就按第九轮反馈改，我这边改的代价都很小）：
    ①「手动节点不许吸附」与「走线要自己接进网络」在**同一格**上会打架：你把一格从路缘正上方拽开几米时，
    左右两条边本来会在**同一个坐标**各接进网络一次 ⇒ 那是零宽度裂缝（能存档、三角化不出东西）。
    现在的规则是**只留贴合内容多的那一侧**，另一侧退回你画的那笔直线（日志 `despike=`）。
    另一种可选的做法是"两侧都不接、整格保持你的折角"，形状更"尊重你那一笔"，但沿路跟随会少一段——两种都合理，我选了不产生退化几何的那一种。
    ② 路口中心点取的是**主接头（度数 ≥3 的那些）的平均**，不是全部成员平均：偏几米的副网络/人行道节点不参与，
    否则就是把中心往路边拽（那正是截图里的症状）。极端不规则的路口（主接头本身偏在一侧）平均出来仍会偏一点，实机看到请指出是哪一种路口。
    ③ 绕行预算**只有比例、没有绝对余量**：这是"距离不进判据"的正面做法，但短弦上"沿路绕一小段"因此更容易被判定为绕太远。
15. **GPT 那份算法正文没有读到**（第八轮反馈 7 给的分享链接：WebFetch 与浏览器取法都被沙箱拦下）。
    这一轮的算法是按游戏数据 + 上面那个根因重写的，**不是照着它改的**。你把正文贴进对话，我再对着比一轮并该改就改。
16. **贴合路径的"经过路口中心"是按顶点判的**：形状上完全共线时简化闸会把这个顶点抹掉（走线仍然从中心穿过，只是不停在那儿）。
    回归壳 J10 就是把这一条按"经过"而不是"停在"写的判据；实机若你要求"每个路口都必须留一格"，那是另一条规则，说一声我改。
